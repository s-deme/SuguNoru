# すぐのる 製品仕様 2.1

## 1. 目的

自宅や職場から出発するとき、複数の電車・バス候補のうち「いま出ればどれに乗れ、どれが早く着くか」を数秒で判断できるようにする。個人の日常利用を対象とし、ログインや共有は設けない。

## 2. 主要ユースケース

1. 利用者は「出かける」「帰る」のどちらかを選ぶ。
2. アプリは、その場面に登録された候補だけを到着見込み順に並べる。
3. 利用者は次発、待ち時間、徒歩・乗車時間、到着見込み、後続2便を一覧で比較する。
4. 候補を開くと、その駅・停留所の平日／土日時刻表を確認できる。
5. 利用者は路線を追加・編集・削除し、ダイヤ改正に追従する。

## 3. 登録項目

| 項目 | 必須 | 用途 |
| --- | --- | --- |
| 場面 | 必須 | 出かける／帰るの絞り込み |
| 交通手段 | 必須 | 電車／バスの識別 |
| 路線名 | 必須 | 候補の識別 |
| 駅・停留所 | 必須 | 乗車地点 |
| 行き先 | 必須 | 方面・目的地の確認 |
| 徒歩時間 | 必須 | 乗車可能な便の判定（0〜180分） |
| 乗車時間 | 必須 | 到着見込みの比較（0〜600分） |
| 到着後徒歩 | 必須 | 降車後から目的地まで（0〜180分） |
| 平日時刻 | どちらか必須 | 月〜金のダイヤ |
| 土日時刻 | どちらか必須 | 土日のダイヤ。空欄時は平日を利用 |
| 祝日時刻 | 任意 | 設定した祝日・臨時休日のダイヤ |
| 有効期限 | 任意 | ダイヤ改正の確認忘れ防止 |
| 乗り場メモ | 任意 | ホーム、出口、停留所位置 |

時刻は `HH:mm` または `HHmm` 形式で、空白・改行・カンマ・読点区切りを受け付ける。重複を除き昇順に保存する。

## 4. 比較ロジック

- 乗車準備完了時刻 = 現在時刻 + 徒歩時間
- 次発 = 乗車準備完了時刻以降の最初の登録便
- 到着見込み = 次発 + 乗車時間 + 到着後徒歩
- 一覧順 = 到着見込みの昇順。同着なら次発の早い順
- 当日の最終便後は、曜日を判定し直して翌日以降の最初の便を表示
- 待ち時間の秒は切り上げ、利用者が便を過大評価しない表示にする

## 5. 画面

### ホーム

- 現在時刻と日付
- 出かける／帰る切替
- 到着見込み順の候補カード
- 最速ラベル、次発、待ち時間、徒歩・乗車時間、到着見込み、後続便
- 空状態からの登録導線

### 登録・編集

- 全登録項目の入力
- 一括時刻入力と形式エラー表示
- 保存、編集時の削除

### 時刻表

- 駅・停留所、路線、方面
- 現在からの次の3便
- 平日／土日の切替
- 時間帯ごとにまとめた全時刻

## 6. データ・プライバシー

- アプリ専用領域にJSONで端末内保存
- ネットワーク権限なし
- アカウント、位置情報、分析SDKなし
- アンインストール時に削除

## 7. 対象外

- 運休、遅延、リアルタイム位置
- 乗換を含む経路探索
- GPSから算出する動的徒歩時間
- GTFS・事業者API・Webサイトからの自動取得
- 自動的なクラウド同期

## 8. 次期候補

外部データ連携の次期優先順位は、(1) 対象地域を決めたGTFS静的データのインポート、(2) 正規APIによる遅延情報、(3) GTFS-Realtime対応。対象地域・事業者の公開条件と再配布条件を個別に確認する。

## 9. 受け入れ条件

- 行き／帰りごとに複数候補を登録できる。
- 徒歩中に出る便は候補から除外される。
- 発車が遅くても早く着く候補を最速として表示できる。
- 最終便後に翌日の便が表示される。
- アプリ再起動後も登録が残る。
- 平日／土日の時刻表を切り替えられる。
- 不正な時刻や空の必須項目を保存しない。
