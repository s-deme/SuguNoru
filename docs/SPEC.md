# すぐのる 製品仕様 2.1.1

## 1. 目的

自宅や職場から出発するとき、登録した都営バスのうち「次に出る便」を数秒で確認できるようにする。個人の日常利用を対象とし、ログインや共有は設けない。

## 2. 主要ユースケース

1. 利用者は「出かける」「帰る」のどちらかを選ぶ。
2. アプリは、その場面に登録された候補だけを次発の発車時刻順に並べる。
3. 利用者は次発、待ち時間、後続2便を一覧で確認する。
4. 候補を開くと、その駅・停留所の平日／土日時刻表と公式サイトからの最終取得状態を確認できる。
5. 利用者は公式時刻表ページを設定し、アプリ起動時または手動でダイヤを更新する。通信できない場合は最終取得データを使用する。
6. 利用者は路線を追加・編集・削除し、ダイヤ改正に追従する。

## 3. 登録項目

| 項目 | 必須 | 用途 |
| --- | --- | --- |
| 場面 | 自動 | ホームで選んだ出かける／帰るタブに登録 |
| 路線・系統 | 必須 | 都営バスの候補から選択 |
| 停留所 | 必須 | 選択した路線・系統の候補から選択 |
| 行き先・方面 | 必須 | 選択した路線・系統の候補から選択 |
| 公式時刻表ページ | 任意 | 交通事業者のHTTPS時刻表ページ。設定時は自動取得の対象 |
| 平日時刻 | 公式ページまたは手入力で1件以上 | 月〜金のダイヤ |
| 土日時刻 | 任意 | 土日のダイヤ。空欄時は平日を利用 |
| 祝日時刻 | 任意 | 設定した祝日・臨時休日のダイヤ |

時刻は `HH:mm` または `HHmm` 形式で、空白・改行・カンマ・読点区切りを受け付ける。重複を除き昇順に保存する。

アプリに同梱する都営バス32系統の候補から、路線・系統、停留所、行き先・方面を選択する。これらの値は手入力しない。候補は時刻表やリアルタイム情報を含まず、時刻表の取得は既存の公式HTTPSページ設定を使う。

## 4. 次発ロジック

- 次発 = 現在時刻以降の最初の登録便
- 一覧順 = 次発の発車時刻の昇順
- 当日の最終便後は、曜日を判定し直して翌日以降の最初の便を表示
- 待ち時間の秒は切り上げ、利用者が便を過大評価しない表示にする

## 5. 画面

### ホーム

- 出かける／帰る切替
- 設定ボタン
- 次発順の候補カード
- 次発、待ち時間、後続便
- 空状態からの登録導線
- 候補ごとの編集、出発通知

### 登録・編集

- ホームのタブに対応する場面へ登録
- 都営バスの候補から、路線・系統、停留所、行き先・方面を順に選択
- 一括時刻入力と形式エラー表示
- 公式時刻表ページからの取得と、取得結果の確認
- 保存、編集時の削除
- 始発・最終・間隔からの等間隔ダイヤ生成

### 時刻表

- 駅・停留所、路線、方面
- 現在からの次の3便
- 平日／土日／祝日の切替
- 時間帯ごとにまとめた全時刻
- 最終取得日時、取得中、取得失敗、保存済みデータ利用の状態表示
- 公式サイトからの手動更新

### 設定・データ管理

- 祝日・臨時休日の日付登録
- JSONバックアップの書き出しと、追加／全置換を選べる読み込み
- 直前の自動バックアップへの復元
- 公式時刻表をまとめて更新
- 登録済み路線の管理
- ウィジェット追加、通知設定、予約済み出発通知の一括取消

### ホーム画面ウィジェット・通知

- ウィジェットに次発の路線、発車時刻、待ち時間を表示し、手動更新できる。
- 選択した便の発車時刻を端末内通知として予約できる。

## 6. データ・プライバシー

- アプリ専用領域にJSONで端末内保存
- 公式時刻表ページの取得時だけネットワークを使用し、最終取得データを端末内に保存（路線登録など他のデータは送信しない）
- アカウント、位置情報、分析SDKなし
- `INTERNET` / `ACCESS_NETWORK_STATE`、通知のための `POST_NOTIFICATIONS`、振動のための `VIBRATE` を要求
- アンインストール時に削除

## 7. 対象外

- 運休、遅延、リアルタイム位置
- 乗換を含む経路探索
- GPSから算出する動的な徒歩・移動時間
- JavaScript実行、ログイン、CAPTCHAを必要とするWebサイトからの取得
- 自動的なクラウド同期

## 8. 次期候補

ODPT APIを都営バスの優先データ基盤として採用する。現時点では認証情報が未設定のため接続しない。実装時は以下を満たす。

- ODPTの利用者登録後に発行されるAPIキーを使用し、キーをソースコードやAPKへ埋め込まない。
- 停留所・時刻表などの静的データには取得日時を時刻表画面のデータ元表示へ出す。
- 将来、位置や到着予測などの動的データを表示する場合は、API応答の生成日時・更新頻度・有効範囲に従う。
- ODPTデータの利用表示、正確性を保証しない旨、アプリの問い合わせ先をアプリ内へ表示する。

## 9. 受け入れ条件

- 行き／帰りごとに複数候補を登録できる。
- 現在時刻以降で最も早い便が各候補に表示される。
- 候補は次発の発車時刻順に表示される。
- 最終便後に翌日の便が表示される。
- アプリ再起動後も登録が残る。
- 公式時刻表を取得した後は、オフラインでも最終取得データで次発を表示できる。
- 平日／土日の時刻表を切り替えられる。
- 不正な時刻や空の必須項目を保存しない。
