# 可読性・人間中心UI監査

## 発見した問題

| 対象 | 修正前 | 問題 |
| --- | ---: | --- |
| 入力欄のヒント / 白背景 | 2.55:1 | 小さい説明文字として読めない水準 |
| ブランド文字 / 淡緑背景 | 4.38:1 | 11spのチップで4.5:1未満 |
| 緑カード上の補助文字 | 4.17:1 | 現在・日付など重要情報が薄い |
| ウィジェット補助文字 | 4.37:1 | ホーム画面の壁紙・照度条件で見失いやすい |
| 入力欄の境界 | 約1.3:1 | 白背景とほぼ同化し、入力可能範囲が分からない |
| 独自Button背景 | 端末依存 | Android標準Tintが重なり、文字と背景が同系色になる可能性 |
| 補助文字 | 11〜12sp中心 | 高密度端末や移動中の一瞥に小さすぎる |
| 無効な通知ボタン | 45%透過 | 意味も文字も判別しにくい |
| 候補カード下部 | 横1列 | 後続便・通知・編集が狭い画面で圧迫される |
| 時刻と待ち時間 | 横1列 | 大きなフォント設定で衝突する |
| 入力フォーカス | 変化が弱い | キーボード・視線移動時に現在位置を見失う |
| 固定高の入力・タブ | 44〜52dp | 大きなフォントで文字が切れる可能性 |
| 数字の字幅 | 可変 | 時計更新時に位置が揺れ、比較しづらい |

## 実施した修正

- 本文色を `#17211C`、補助色を `#4A5D53`、ヒント色を `#65786E` に整理。
- ブランド色を `#006C4F`、濃色を `#004D39` に整え、白文字との比率を6.45:1に維持。
- 背景・面・面の変種・境界・操作枠・状態色を意味的トークンとして分離し、画面ごとの直値を削減。
- 端末設定に追従するダークテーマを追加。本文、補助、ヒント、カード枠、注意、エラーの各組み合わせを単体テストで検証。
- 通常の本文・説明は原則14sp以上、操作ボタンは14〜16sp、チップは太字13spへ拡大。
- ウィジェットの全テキストを白へ統一し、最小文字を13spへ拡大。
- 入力欄と操作カードに白背景比4.50:1の境界を付与。
- 入力フォーカス時は2dpの緑枠を表示。
- Button・EditText・Spinnerの標準Tintを解除し、明示した色が端末テーマで上書きされないようにした。
- すべての独自ボタンに押下リップルとキーボードフォーカス枠を追加。
- 時刻と待ち時間、後続便と操作を縦方向へ分離し、狭幅・大きな文字でも衝突しにくくした。
- 無効な通知ボタンを薄く表示せず、試算中は表示しない方式へ変更。
- 入力欄・タブ・見出しの固定高を廃止または最小高へ変更し、文字拡大時に伸びるようにした。
- 時計・発車時刻・時刻表に等幅数字を指定し、更新時の視線移動を抑えた。
- フォント上下余白と行間を確保し、日本語グリフの切れと行の詰まりを防いだ。
- 通常カード、入力欄、設定項目の境界を強め、色だけでなく輪郭でも領域を識別可能にした。

## UI刷新（2026-08）

- ホームの情報順を「利用場面 → 次発 → 待ち時間 → 到着見込み → 内訳」に再編し、最速候補を面色・枠・ラベルで強調。
- 登録フォームを「基本情報」「所要時間」「時刻表」「補足」の4セクションへ分割。
- 設定画面を目的別カードへ整理し、有効／停止状態を色だけでなく文字ラベルでも表現。
- 画面幅380dp未満またはフォント倍率1.2以上では、時計・日付と所要時間入力を縦積みに切り替える。
- 時刻表、ページヘッダー、固定保存領域、ウィジェットを同じ角丸・余白・状態表現へ統一。

## 画面簡素化（2026-09）

- ホームからアプリ名・説明、現在日時、日時シミュレーション、最速強調、到着見込みと所要時間の内訳を除外し、出かける／帰るタブ、設定、次発、待ち時間、後続便に絞った。
- 追加先の場面はホームで選んだタブから自動設定し、登録フォームの場面・交通手段・所要時間・補足入力を除外した。
- 路線・系統、駅・停留所、行き先・方面は入力枠ではなく、候補選択後の読み取り専用ラベルで確認する形にした。

文字ペアはWCAG AAの4.5:1以上、操作境界は3:1以上を下限とする単体テストで退行を防止する。

## システム領域・安全領域監査

### 発見した問題

- Android 11以降でコンテンツを画面端まで描画していた一方、表示中のバーだけを基準に余白を付けていたため、バーの表示状態や端末形状によってヘッダー・フッターが重なる余地があった。
- ナビゲーションバーを白背景にしていたが、暗色アイコン指定がなく、端末によって白いアイコンが同化する可能性があった。
- ノッチ、横画面の側面バー、必須ジェスチャー領域、ソフトキーボードを安全領域の計算に含めていなかった。

### 実施した修正

- Android 11以降では、非表示時を含むステータスバー・ナビゲーションバー・ディスプレイカットアウトを安定領域として取得する。
- 必須システムジェスチャー領域とIME領域も取得し、各辺で最大の余白を画面ルートへ適用する。
- Android 8.1以降では白いナビゲーションバーに暗色アイコンを明示し、Android 11以降ではステータス・ナビゲーション双方のアイコン表示をフォーカス復帰時にも再適用する。
- IME表示時は `adjustResize` と下端安全領域を併用し、入力欄と操作領域がキーボード背面へ隠れないようにする。
- 安全領域の合成ロジックは、上端・下端・横画面の側面・IME優先を単体テストで固定する。
