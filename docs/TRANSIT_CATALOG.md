# 路線候補の出典と検証

## 2026-09-19の修正

旧一覧57候補には、公式一覧にない「都10・都20・都22・都23・都26・都40・都44・都58・都64・都65・都75・都88・都97」が含まれていた。これら13候補を新規選択から削除した。過去の一覧全体を検証済みと扱ったのは誤りだった。

残りは東京都交通局の[公式系統一覧](https://tobus.jp/sp/blsys/route?trn=top_stop)とODPTの実データに照合した。都03・都05-1・橋63の起終点を訂正し、王40を王40甲へ修正。錦13甲・錦13乙は現在の提供単位である錦13に統合し、43候補とした。錦13の分岐は経路と乗降停留所で区別する。都05-1は晴海埠頭発着であり、東京ビッグサイト発着は都05-2という別系統。

## 停留所が見つからなかった原因

- ODPTの実タイトルは「都０７ 門前仲町行」など。旧処理は空白を削除してから、系統名の直後が文字なら別系統と判定していた。日本語の行き先も文字なので正しい経路を除外していた。
- アプリ独自IDを大文字化してODPT路線IDを推測していた。実際は都01が `T01`、都07が `To07`、業10が `Nari10`、錦11が `Nishiki11` などで、推測は成立しない。
- さらに標柱IDを40件ずつ問い合わせていたが、実APIが `too many OR condition in owl:sameAs` で拒否した。10件ずつへ修正し、都07の6経路・43標柱を同じ検索条件で取得できることを実通信で確認した。
- 錦13甲・乙のように、一覧の系統区分とAPIの提供単位にも不一致があった。

修正後は確認済みの `odpt:busroute` をカタログに保持し、事業者IDと路線IDで完全一致させる。タイトルの表記や行き先には依存しない。誤った候補を全事業者経路の検索で補う処理も削除した。

## 実データの確認結果

取得日：2026-09-19。提供者：東京都交通局、提供基盤：公共交通オープンデータセンター（ODPT）。

- [BusroutePattern公開API](https://api-public.odpt.org/api/v4/odpt:BusroutePattern?odpt:operator=odpt.Operator:Toei)：757経路取得。
- [BusstopPole公開API](https://api-public.odpt.org/api/v4/odpt:BusstopPole?odpt:operator=odpt.Operator:Toei)：3,690標柱取得。
- 同梱43候補に対応する234経路について、2停留所以上・順序番号の重複なし・全標柱の公式名称取得を確認。
- 各候補の実ID、経路数、標柱数は[照合結果CSV](transit-catalog-audit.csv)に記録。

これは取得日時点のスナップショットであり、全都営バス系統の収録や将来の運行を保証するものではない。アプリは利用時にODPTから経路・停留所を取得する。公開APIでデータを検証したが、ユーザーのアクセストークンを使用した端末通信は未検証。

## 保存済み登録と選択動作

旧登録の表示名・時刻表・キャッシュは削除しない。訂正前の有効な系統名も公式IDへ解決する。存在を確認できない13候補の旧登録も表示・編集可能に保つが、ODPT取得時には路線の選び直しを案内し、推測した別路線へ自動置換しない。

乗車・降車候補は経路別の全停留所から作る。降車候補は乗車後に到達できる停留所のみ。往復・分岐・循環を別経路として扱い、時刻表もその区間を実際に走る便に限定する。通信失敗時は現在の選択とキャッシュを保持する。

## 回帰検証

`TransitCatalogTest` で公式ID・旧名称・誤候補の除外を確認する。`JourneySelectionTest.testOfficialRouteIdentityIgnoresDestinationTitle` では実APIのタイトル例を用い、行き先付き・タイトル欠落でもIDで選べること、別事業者や別路線を混ぜないことをAndroidのJSON実装で確認する。

JDK 17以上とAndroid SDKを設定し、単体テスト・Lint・ビルドは `./gradlew.bat testDebugUnitTest lintDebug assembleDebug`。エミュレーターは個人データと別パッケージを使う `./gradlew.bat -I scripts/verification.gradle connectedDebugAndroidTest`。

実行結果：単体41件、Androidエミュレーター5件が成功。Lintはエラー0件・警告4件。端末テスト用のGradle補助依存がオフラインキャッシュになかったため、検証用APKをビルドし、ADBの `am instrument` で同じテストを実行した。
